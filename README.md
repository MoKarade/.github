# MoKarade/.github

Le dépôt commun aux apps de Marc.

- **Issues** : le travail qui touche plusieurs dépôts (chantiers, missions, tâches communes).
- **`docs/`** : les règles communes, à commencer par le [cycle de vie d'une tâche](docs/cycle-de-vie-tache.md).
- **Graphe de code** : hooks et MCP `graphify` posés (0 jeton) ; `scripts/graphe.sh query|affected|path|explain` avant de grepper ; wiki : `graphify-out/wiki/index.md`. Détail : [docs/graphe-code.md](docs/graphe-code.md).
- **`scripts/fumee.mjs`** : le test de fumée appelé par `fumee.yml` ; tests : `node --test scripts/fumee.test.mjs`.
- **`scripts/garde-fou.mjs`** : le contrôle « Garde-fou » appelé par `.github/workflows/garde-fou.yml` de chaque dépôt. Il décide si une PR des chemins protégés peut être fusionnée seule par Mergify ; tests : `node --test scripts/garde-fou.test.mjs`.
- **`scripts/relecture-ia.mjs`** : la relecture IA des PR au Garde-fou rouge pour une raison levable (références à un secret, cas de test), lancée toutes les 10 minutes par `relecture-ia.yml`. Règles, limites et secrets : [docs/relecture-ia.md](docs/relecture-ia.md) ; tests : `node --test scripts/relecture-ia.test.mjs`.
- **Workflows réutilisables** : les contrôles communs, écrits une fois et appelés par chaque dépôt avec `uses: MoKarade/.github/.github/workflows/<nom>.yml@main`.
  - `securite.yml` : gitleaks sur les commits de la PR, OSV-Scanner sur `package-lock.json`, CodeQL (dépôt public seulement). Actions épinglées par SHA. Un risque accepté s'écrit dans un `osv-scanner.toml` du dépôt, avec sa raison et sa date. Ce dépôt l'applique à lui-même (`securite-ci.yml`).
  - `conformite.yml` : la grille de conformité (15 lignes) lue dans le dépôt appelant, tableau ligne par ligne dans le résumé du job. Détail : [docs/conformite.md](docs/conformite.md). Lancement à la main : workflow « Essai de la conformité ».
  - `fumee.yml` : après un déploiement de production, vérifie la santé (`{ ok: true }`), que le summary refuse sans jeton et répond avec, et que la page de connexion répond ; rouge sinon. Logique et tests dans `scripts/fumee.mjs`. Lancement à la main : workflow « Essai de la fumée ».
  - `surveillance.yml` : toutes les 15 minutes, sonde `/api/sante` des apps listées dans `surveillance/apps.json` (avec le secret `UPTIMEROBOT_API_KEY`, clé en lecture seule, elle lit à la place l'état des moniteurs UptimeRobot, un par URL de santé ; un moniteur absent, en pause ou pas encore mesuré est « non mesuré » ; si UptimeRobot ne répond pas, elle sonde elle-même et le dit) ; une app muette ouvre une issue `panne`, son retour la ferme. Elle relève aussi le dernier déploiement de production de chaque app (publié par Vercel dans GitHub) : un échec ouvre une issue `panne` « Déploiement en échec : <app> », le déploiement suivant réussi la ferme ; un dépôt privé est « non mesuré ». Logique et tests dans `scripts/surveillance.mjs` et `scripts/deploiements.mjs`. Essai à la main : « Run workflow » avec un nom et une URL, ou `deploiement-essai` = `echec` puis `succes`. Retour en arrière (`scripts/retour-arriere.mjs`, secret `VERCEL_TOKEN`, inactif sans lui) : une app dont la santé est rouge juste après un déploiement est remise sur la version précédente et une issue `incident` s'ouvre ; « Run workflow » avec `retour-controle` lit Vercel sans rien changer.
  - `rapport-hebdo.yml` : chaque lundi (10:00 UTC), une issue `rapport` « Rapport de la semaine du AAAA-MM-JJ » : vitesse, qualité, santé du backlog des dix dépôts ; le premier lundi du mois, la revue de la grille. Ce qui n'est pas mesuré (dépôts privés, Vercel, tests instables) est dit « non mesuré ». Logique et tests dans `scripts/rapport-hebdo.mjs`. Lancement à la main : « Run workflow ».
  - `captures.yml` : sur une PR qui change un écran, lance l'app avec les données fictives des tests (jamais la production), photographie les pages listées sur la branche par défaut puis sur la PR, range les images dans la branche `captures` (sous `pr-<n>/`, historique gardé) et tient UN commentaire « avant / après » à jour. L'appelant donne la commande de démarrage et les pages. Logique et tests dans `scripts/captures.mjs`. Essai : `captures-essai.yml` sur `tests/captures-demo/`.

On change une règle par une PR sur ce dépôt.
